# User interface

## Model tree

Present these items in the project tree in this order:

```text
GERCHBERG-SAXTON HOLOGRAM (application display name, visually styled in uppercase)
├── Inputs
│   ├── Target SVG
│   ├── Design parameters
└── Study
    └── Far-field hologram study
```

Use the existing FullMeta Model Editor tree. The root label is the selected application's display name (the example says **Gerchberg-Saxton Hologram**, styled in uppercase), not the editable project `metadata.name` (which remains visible in project settings). It has exactly two branches directly below it: Inputs and Study. Do not insert an extra application-name group between the root and these branches. Inputs has exactly two selectable leaf rows: Target SVG and Design parameters. The latter binds to `/model/illumination`; keep that machine path unchanged. These rows have no disclosure handles or child rows; selecting one opens its shared Settings controls directly. Target SVG Settings contain an editable SVG source and an editable physical viewBox width in rad/µm; there is no intervening drawing, shape, or extra application-name level. The SVG source uses the shared multiline Value Control, fills the available Settings value-column width, starts 120 CSS pixels high, and can be resized vertically. Do not add a custom drawing widget or separate editor surface. The project has one fixed Study row. Its Settings contain editable GS iteration count and initialization seed, **Run Study**, **Clear Results**, and a Run history panel; follow [contracts/study-workflow.md](contracts/study-workflow.md) for exact paths, selection effects, action states, scene transitions, progress, errors, and saved-result behavior.

## Drawing and settings

The SVG source must be well-formed, self-contained XML with a positive `viewBox`. SVG coordinates have an origin at the top left, with x increasing rightward and y increasing downward. Map the full SVG viewBox to the centered square far-field span named by `targetWidthRadPerUm`; artwork scale within the viewBox sets the letter size. Rasterize it to the selected square grid while preserving aspect ratio, then map rows into Cartesian coordinates with positive y/ky upward. The Graphics Console previews this binary mask and visibly states this coordinate conversion and physical k-space span. The SVG background is transparent; artwork color is ignored. In the raster, alpha coverage at least 0.5 maps to target intensity `1`; lower coverage maps to `0`. The SVG source and target width remain persisted inputs.

Design parameters Settings expose editable wavelength, square grid size, sample pitch, circular aperture radius in µm, and scalar illumination amplitude expression `A(x,y)` with `x` and `y` in µm. The circular aperture mask is applied to the amplitude before the near-field constraint. `A=1` means uniform illumination over the disk. The supported expression grammar and aperture rules are in [contracts/scalar-far-field-gs.md](contracts/scalar-far-field-gs.md). When Design parameters is selected, Graphics Console plots the relative incident amplitude profile over the full physical x-y plane, including outside the aperture, draws the circular aperture boundary, labels `x` and `y` axes in µm, and displays an amplitude scale and physical aperture diameter. The aperture overlay must use the same data-to-screen mapping as the raster, so it remains registered while zooming and panning. This is a single raster-grid `plot-2d` view, not a custom canvas renderer.

The selected Study's Settings expose GS iterations and initialization seed, with declared defaults of 40 and 20261110, as well as **Run Study**. Show physical units for spatial quantities and enforce schema-declared ranges. Following FEM's panel layout, the upper-right Graphics Console displays the target mask, metasurface phase profile, and final reconstructed hologram together when Study is selected. Selecting Target SVG shows its target view; selecting Design parameters shows its illumination profile view. Use the same shared `plot-2d` raster-grid view for both single-plot input selections and for each of the three Study result plots. The shared widget owns independent raster-view interactions: wheel zoom is centered at the pointer, left-drag pans, and double-click resets to the initial axes. Zooming out must stop at the plot's original axis range and must not reveal a wider domain than its initial view. Both the raster pixels and any overlays must scale and pan with the axes; ticks and labels update to the visible limits. Callers draw view-dependent annotations through the plot's overlay hook; a plot view change updates only that plot region. A zoom or pan interaction in the three-plot Study view redraws only the affected plot region; sibling plots remain visible without a full-console repaint or blink. Zoom and pan must work when a view contains only one plot as well as when plots are arranged together.

## Validation and graphics

The project-root **Validate** action uses the shared Model Editor JSON Schema and declarative V-rule validation service. Keep the shared panel heading **Graphics Console**. Selecting Design parameters shows the beam and aperture; selecting Target SVG shows the target pattern with `kx` and `ky` axes in rad/µm, displayed Nyquist extent `±π/Δx`, physical target span, and the propagating-wave circle when visible. The SVG is rasterized into Cartesian coordinates before the shared `plot-2d` widget displays it, keeping the letter upright with positive `ky` upward. Show that SVG source coordinates use top-left origin/y-down and are converted to Cartesian positive-`ky`-up. When Study is selected, the Graphics Console subtitle identifies both plotted domains: metasurface `x`, `y` in µm for phase and far-field `kx`, `ky` in rad/µm for target and reconstruction. Use the same shared `plot-2d` raster-grid mode for all three result plots, ordered left-to-right as **Metasurface phase**, **Reconstructed hologram**, and **Target hologram**; center each short title over its own plot. The zoom and pan behavior applies consistently to single-plot Target SVG and Design parameters views and to each Study result plot. The `plot-2d` surface mode and separate `plot-3d` widget remain unchanged. Do not put result images in Settings. Display normalized intensity and physical axes; absent or stale outputs have explicit states. Run Study reports progress, stop, completion, or a readable error through the shared Model Editor operation UI. See the normative [Study workflow contract](contracts/study-workflow.md).
