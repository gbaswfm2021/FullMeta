# Validation

Validate the stored project structure and operation inputs before calculation.

| Input | Required validation | User repair |
| --- | --- | --- |
| Target SVG | Nonempty, well-formed SVG XML; `svg` root; four finite `viewBox` values with positive width and height; no script, event-handler attributes, embedded documents, external resource references, or executable/imported content; raster mask has foreground pixels. | Select Target SVG and correct the multiline source. |
| Target far-field span | `targetWidthRadPerUm` is finite and lies between one bin, `2π/(NΔx)`, and the plotted Nyquist span, `2π/Δx`. This is checked against the selected grid and sample pitch. | Increase the span to at least one bin, or reduce it to fit the plotted k-space range; change grid size or sample pitch if needed. |
| Grid size (V-rule) | The root `x-fullmeta-rules` declarative program requires `/model/illumination/gridSize` to belong to `[64, 128, 256]`. The native Study also checks the supported grid before calculation. | Choose 64, 128, or 256 samples per side. |
| Propagating-wave support | Every nonzero rasterized target bin satisfies `kx² + ky² ≤ k₀²`, where `k₀=2π/λ`. The JavaScript Study preflight and Rust engine both reject nonpropagating target bins; the UI shows the disk boundary when it falls within the target plot. | Reduce the physical target width or artwork size, or choose a wavelength and sample pitch for which the intended target is propagating. |
| Wavelength | Finite positive value with a supported length unit. | Enter a positive wavelength and choose a supported unit. |
| Illumination amplitude | Expression parses using the supported scalar grammar; evaluates to finite, nonnegative values at every full-plane sample; and is positive at least once inside the circular aperture. Missing/empty expression means uniform amplitude `1`. | Correct the expression or enter `1`; the error identifies an invalid value. |
| Circular aperture | Physical radius in µm is finite, greater than zero, and no larger than half the physical grid width (`N × sample pitch / 2`); illumination has at least one positive sample within the disk. | Choose a radius within the displayed sampled-plane extent or change the illumination expression. |
| Sample pitch | Finite positive value; it sets the physical square width `L=NΔx` and far-field bin interval `Δk=2π/(NΔx)`. | Enter a positive sample pitch. |
| Study iterations | `model.study[0].iterations` is an integer from 1 through 100; default 40. | Select Far-field hologram study and enter an iteration count in range. |
| Study seed | `model.study[0].seed` is an integer in the supported 32-bit unsigned range; default 20261110. | Select Far-field hologram study and enter a valid seed. |
| Study collection | Exactly one Study item is present; its ID is nonempty and stable, its name is nonempty, and its type is `farFieldPhaseOnly`. | Restore the required Study item; Study add, delete, duplicate, and rename actions are not offered. |

The project-root **Validate** action first runs JSON Schema validation and then the schema's single declarative grid-size V-rule; if either returns an error, those are the reported validation errors. It also runs the application's non-structural input checks (SVG syntax/safety, physical target span, illumination expression/radius, and fixed Study identity). The grid V-rule requires exactly `64`, `128`, or `256` at `/model/illumination/gridSize`; its diagnostic path is that same pointer, and its repair message is `Square grid size must be 64, 128, or 256 samples per side.` Run Study repeats validation after committing Settings drafts and before saving or launching the calculation. The JavaScript target rasterizer then checks the actual nonzero bins against the wavelength-dependent propagating disk; the Rust engine repeats the supported-grid, numeric-array, illumination, and propagating-target checks before iteration. An empty target is invalid. A target that rasterizes to zero intensity is invalid. Reject non-finite result arrays before saving and report the failed operation without replacing the inputs or a prior completed run. Structural and declarative validation alone do not establish successful calculation; numerical acceptance is defined in [ACCEPTANCE.md](ACCEPTANCE.md).
