# Architecture

## Components and ownership

| Component | Responsibility |
| --- | --- |
| Application schema | Declares the project model, constraints, ordered Inputs and Study tree branches, selection rules, Settings, and operation interface. |
| Application package and JavaScript | Handle editor/UI integration, validate and rasterize the SVG target for an engine request, coordinate Study operations and project-local run history, and project the selected input/result view into the Graphics Console. |
| Application Rust engine | Evaluate the illumination expression and circular aperture, execute the FFT-based GS calculation, and save or clear completed project-local run artifacts. One Windows executable at `.runtime/x86_64-pc-windows-gnu/release/gs-engine.exe` exposes the three operations `--run-study`, `--save-run`, and `--clear-results`. |
| Shared FullMeta Model Editor | Interpret the schema, present the model tree and shared Settings controls, route project documents, commit/save drafts, and provide operation progress and cancellation controls. |
| Example project | `projects/gerchbergsaxton-letter-m/gerchbergsaxton.json` supplies the editable Letter M target and starting parameters as an ordinary project document. |

Keep the project tree shallow: its root label is the application display name from the selected schema (visually styled in uppercase); `metadata.name` remains the editable project name in project settings. Inputs and Study are directly below the root; Inputs contains selectable Target SVG and Design parameters rows. Design parameters is the visible label for the existing `/model/illumination` object; do not rename that JSON key. The selected Study's Settings contain GS iterations, initialization seed, **Run Study**, **Clear Results**, and saved Run history. Each input row selects its actual model object so its Settings are directly editable. Target SVG uses the shared multiline Value Control, full value-column width, 120 CSS pixel initial height, and vertical resize. Study actions and history follow FEM's selected-row pattern. Rasterize the same SVG input for the target preview and GS target constraint. Do not add an application-specific drawing or settings widget. Keep selection and progress outside persisted scientific inputs; keep completed outputs in project-local run directories rather than model JSON.

## Operation boundary

The user edits the SVG target and Design parameters through shared Settings, then selects the Study row, adjusts its iterations and seed, and starts **Run Study** from its Settings. Design parameters is the UI label for the persisted `/model/illumination` object. JavaScript rasterizes the saved SVG to a binary target mask and passes that interface data plus the saved design and Study inputs to the single application-local Rust engine. Rust evaluates the illumination and circular aperture, performs the complete FFT-based GS calculation, and returns target, phase, reconstructed intensity, and completion data without rewriting inputs. Phase is undefined where effective illumination is zero; those samples are serialized as JSON `null`. The same executable owns project-local result saving and clearing. JavaScript handles operation lifecycle, run-history integration, result resolution, and plotting. In FEM's Graphics Console panel above Settings, the Study scene displays metasurface phase, reconstructed hologram, and target hologram from left to right; selecting Target SVG shows the target in physical `kx`, `ky` coordinates, and selecting Design parameters shows the incident beam and aperture. Each raster plot supports independent wheel zoom, drag pan, and double-click reset with axes updated to the view. A result is current only for the exact input revision and Study settings that produced it. The app uses shared Model Editor controls and does not register a custom field widget.

Application code owns target rasterization, the domain algorithm, and result projection. Within the application, JavaScript handles editor and interface duties while Rust owns illumination evaluation, aperture application for the solver, FFTs, GS iterations, and project-run file operations. Shared platform code owns document opening/saving, schema interpretation, tree/Settings editing, shared widgets, command dispatch, and common presentation hosting.
