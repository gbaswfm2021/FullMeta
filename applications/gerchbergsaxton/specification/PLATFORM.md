# Platform profile

Use the established FullMeta application catalog, interpreting schema, Model Editor, project-document, frontend provider, and command interfaces. The shared contracts are listed in the [application platform contract](../../../platform/docs/application-platform-contract.md).

The application owns its schema, SVG-to-mask rasterization, GS calculation, Study/result selection projection, and example project definition. Use the existing FullMeta schema-driven Model Editor and shared widgets, including the shared tree, editable Settings controls, project save, root-level Validate action, selection action placement, Graphics Console, and Operation strip. Follow FEM's root-level Validate and selected-Study-row action patterns. Do not add an application-specific drawing, result, or settings widget. The app must not add a parallel document format or bypass the shared project editing and save workflow.

The app is discovered through `applications/gerchbergsaxton/catalog.json` and is the compact reference application bundled with a FullMeta platform deployment. Its projects reference `applications/gerchbergsaxton/gerchbergsaxton.schema.json` using the normal workspace-relative schema routing convention. The Letter M example remains a separate project document under the workspace's project storage. FEM is a separate application users may add after installing FullMeta; it is not a prerequisite or runtime dependency of this reference app.

The full platform contract is selected by [Study workflow](contracts/study-workflow.md): the app uses the shared Model Editor validation service, shared Save path, and shared Operation progress/Stop presentation. Its grid-size V-rule is authored and maintained as the schema's declarative `x-fullmeta-rules` program through Schema Editor's Validation Requirements UI; do not replace it with application-only root validation. The application-specific Rust engine performs illumination evaluation, aperture application, FFTs, and GS iterations; JavaScript handles the editor/interface, target rasterization, physical preflight, operation coordination, run-history integration, and graphics. One executable is built inside `gs-rust/` and is deployed there; `.build/` contains Cargo intermediates only. FEM's native solver and mesh preparation are not dependencies of this application.

## Schema author metadata

The interpreting schema declares the top-level `author` string as `Jensen Li`. Schema Editor shows it in Document Settings. Application schema authors must populate this field, following the shared [application specification convention](../../../platform/docs/application-specifications.md#application-author-metadata), so each application schema identifies its author consistently with FEM.
